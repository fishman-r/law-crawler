# 法域、模式、批次与最新版本选择

## 输入确认

按SKILL.md完成用户输入确认。新批次CLI要求`--jurisdiction`及`--mode metadata|content`；非交互缺mode时明确报错，不默认下载原文。

`jurisdiction_registry.py` 只读工作区 `countries/*/index.md`；别名仅当其规范法域已登记时生效。EU 成员从索引章节读取：德国、法国、荷兰、意大利的登记不能外推到另外 23 个国家。`--index` 若提供，须与法域登记索引一致。校验不匹配会在网络和批次创建前失败。

## 批次

`--batch-id` 可指定安全批次标识，缺省生成新 ID。批次计划记录法域、模式、索引、平台、限量、目录、重试及其他执行参数。`--plan-only` 只保存参数计划，不访问网络；待执行项尚未发现时不能声称已有完整法规目录。

批次位于配置基础目录 `.batches/<ID>/`，后续执行记录位于 `attempts/0001/` 等子目录；原文 URL 候选快照记于 `candidates.json`。实际文件按国家目录保存。批次信息不是下载库存，必须结合文件元数据和状态核对。

`--rerun-batch <ID>` 使用该计划已确认的法域和模式，保留先前尝试，重新执行失败/待处理项。`--rerun-all` 重跑全部项，成功缓存仍需本地验证。重新传入的法域和模式须与计划一致，变更任务范围应创建新批次。计划尚未发现候选时重跑会先执行发现阶段。

默认重跑先验证所有前轮成功文件，并为可复用的不同内容预留总限量与平台限量，再处理失败/待执行项；缓存成功同样占用本轮额度，不能借重跑继续采集前轮因限量跳过的对象。损坏或缺失文件不算有效成功，仍可在额度内修复。旧执行若曾产生超额成功，本轮按冻结候选顺序限额呈现，其余标为限量跳过，历史文件和报告保留。报告本轮文件数与国家目录历史库存数应分开核对。

## 日期与选择

法规分组依赖有证据的法规身份，不能单靠标题相似。跨版本和跨来源优先选择有证据的最新 `published_at`；记录选择原因和所有候选，来源日期含义须保留。发布日期指法规公布日期；抓取时间、HTTP Date、网页 `updated_at` 不能代替。未知日期或同日并列不虚构唯一最新，明确标为待确认；需要选择执行项时使用可复现的来源排序，全部候选仍保留。

最新选择不会删除历史原件和来源。SHA-256 相同表示字节相同，应合并来源；不同内容须保留历史关系。不能以来源数量多、网页排序靠前或某个平台固定优先等规则覆盖发布时间比较。

`--limit`、`--per-platform-limit` 约束原文文件处理数量，元数据目录观察主要受 `--max-details` 限制，不代表目录条数限量。

## 两种模式

- `metadata`：采集有限目录和详情元数据，保存每候选的来源、身份、日期、链接与状态，不请求法规原文附件。
- `content`：依据已选择对象请求官方原文，校验格式、去重、保存文件及独立元数据；HTML/XML/JSON 法规文本转换为 Markdown，并保存原始响应及转换溯源。

每份实际下载内容都有元数据；目录候选、失败文件记录也有状态和原因。原始响应只是审计副本，不是未经校验的法规采集成功。

## 重试与报告

`--max-attempts 3` 默认包含首次请求，即失败后最多再试两次。`--backoff-base 1` 指指数退避基数，等待由执行器控制；拒绝错误页、非官方主机或超限文件等校验失败应记录精确原因。单项达到上限后继续其他项，不能无限重试。缓存复用记为成功缓存状态，不能伪造网络尝试。

执行完成后，每次尝试生成机器 JSON、Markdown 和固定版式 HTML 报告。HTML 应能离线阅读，展示任务摘要、平台状态、候选/文件结果和失败原因，所有外部内容须转义。报告明确限定本次样本范围，列出待确认日期、未适配平台与受阻来源。
