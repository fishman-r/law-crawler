# 批量原始归档与覆盖验收

## 定义完整性

将“全量”分为来源覆盖、目录穷尽、原件完整归档、派生处理和独立审核五个可分别核查的状态。列出登记来源、实际遍历的目录、文种、时间和地域范围；保留未知分母。仅在这五项都有实际证据时声明所述范围完成。不要将平台统计、末页推算、首屏下载、模型处理成功或文件哈希当成全国覆盖证明。

按印尼官方原始文种收集PERMA（最高法院条例）和SEMA（最高法院通函/司法指导），说明其与中文“司法解释”不必具有相同法律地位。区分个案Putusan、草案、摘要和正式规范文件。其他法院规范类别先核实索引及适配器支持，不自动扩大到判决库。

## 建立归档队列

使用独立包内的命令；用实际解释器和绝对路径替换占位符。默认针对法域索引全部来源；指定`--platform`时在报告中保留选定子范围。不要将默认普通下载命令的有限数量扩大后冒充分页穷尽。

```text
python "SKILL_DIR/scripts/bulk_archive.py" --root "WORK_ROOT" --jurisdiction Indonesia --batch-id id-full-ARCHIVE_ID --phase all
python "SKILL_DIR/scripts/bulk_archive.py" --root "WORK_ROOT" --jurisdiction Indonesia --rerun-batch id-full-ARCHIVE_ID --phase all
```

按国家配置的`downdloadDir`保存`Indonesia/pipeline/bulk/BATCH/`。先冻结索引快照哈希、来源、重试和文体配置，再访问网络。逐页持久化`state.json`；保留全部目录、详情和已发现原文的原始响应到共享`pipeline/raw/`，失败响应同样保留，不送入翻译。下载所有适配器明确发现的原文链接，不先按最新版本或首选格式删减；附件发现仍取决于平台适配器能力。保留URL、来源和SHA关系，正文身份与有效性保持独立待核。

使用`discover`、`capture`、`export`分别执行目录、详情原件和导出，或用`all`顺序执行三阶段。使用`status`读取断点并生成JSON、Markdown和HTML报告。每次响应默认最多3次总尝试，403等明确失败不必耗尽重试；TLS超时与暂时错误执行有界退避。达到`--max-pages`保护上限、出现重复页面、分页证据不足或目录失败时保留未完成状态。

当前MA适配器分别跟随PERMA、SEMA目录的官方分页链接，记录每页SHA、详情和后续页。其余只支持首屏的适配器必须报告`incomplete`，不能将没有更多已发现链接解释为全站穷尽。JDIHN生产路由、访问控制和各地来源需按本次观测重新核验。

迁往服务器执行下载时，先停止来源机器的采集及等待处理任务，保存断点；只部署完整skill源码及所选法域索引，不连带启动模型或复制提供方凭据。现有批次和raw缓存包含绑定签名的绝对路径，不能仅修改`--root`或重写plan后冒充原批次。使用目标机器的新工作区和新批次；需要迁移断点时另行记录原始快照、迁移映射及校验，不覆盖来源证据。核对远程实际进程、日志增量、文件哈希及业务报告；SSH可达、服务active或退出0均不单独代表法规下载成功。

## 纯下载续跑

对用户明确只要求原始文件的任务，保留原件、逐文件收据、必要元数据和下载报告后停止，不自动创建处理清单或运行OCR、翻译、独立内容复核。先用`bulk_archive.py --phase discover`完成实际支持范围的目录发现，再按原冻结批次续跑：

```text
python "SKILL_DIR/scripts/bulk_download_fast.py" --root "WORK_ROOT" --jurisdiction Indonesia --rerun-batch BATCH_ID --workers 2
```

默认使用2路、最多5路下载，按详情隔离小断点，由单个写入者合并主状态，减少每次响应重写全量JSON的开销。使用可等待的逐URL锁合并同一链接的并发请求；沿用原批次的官方主机、节流、3次请求上限及有界退避，不以增加并发绕过403或访问挑战。保留原计划及签名，另存带源码哈希的本次执行策略。

校验已完整归档详情的全部文件SHA后跳过，恢复未开始或中断项；默认保留已有`failed/incomplete`，仅在明确使用`--retry-failed`时重试，不反复下载已知403或超出既定体积上限的文件。重跑及结束报告仍须列出这些缺口，不能把跳过失败项计为下载成功。部署新版本前核对剩余队列；当前任务已结束时不为切换版本重跑全部已成功文件。

## 处理与复核队列

读取批次`metadata.json`、`export-exclusions.json`和`manifests/`。导出仅接纳完整2xx、哈希验证通过且具官方详情身份线索的支持格式；错误页、未知格式或身份缺失原件继续归档，列为待适配或待确认。保留每件全部来源及元数据，不用同名标题删除版本。处理前的这项门槛不替代独立法律正文身份核验。

区分每个链接的正文、正式附件、草案及相关资料角色。同页链接不自动继承主文件的正式身份；不依据URL或PDF文字层中的单一“草案”关键词判定。结合详情链接说明、可见页图、番号、签发和公布信息核验；保留隐藏模板文字与可见内容不一致的证据。所有文件继续原始归档，未确认的相关文件暂停进入正式法规翻译队列。

```text
python "SKILL_DIR/scripts/bulk_process.py" --root "WORK_ROOT" --jurisdiction Indonesia --manifest-dir "COUNTRY_DIR/pipeline/bulk/BATCH/manifests" --output "COUNTRY_DIR/pipeline/bulk/BATCH/processing" --model-config "MODEL.json" --ocr-engine apple-vision
```

归档仍在进行时，追加`--await-export-seconds 86400`建立有界等待任务。先冻结生产者计划、模型与文体，每5秒检查`active-manifests.json`；导出就绪且哈希通过后才冻结实际输入并开始处理。等待期间不运行OCR或模型；超时保留`pending_export`及原因。生产者计划或配置变化须停止核对，不能悄然接收新范围。单独检查`await-export-state.json`，不要把等待中视为已处理。

选择已安装OCR引擎；macOS可用Apple Vision，其他环境可选择已安装Tesseract及印尼语言包。使用`none`保留文字层处理，扫描件将失败待OCR。完整PDF逐页OCR后尝试自动表格重建；检测失败保留原因及OCR，不将其标记为关系准确。详细方法、依赖和图表边界见[本地OCR](local-ocr.md)。

逐件创建冻结的三阶段批次，保留原文、中英文派生稿和独立`review-request.json`；采用中国大陆中文、英国英文的冻结文体，语义与文体分别审查。配置变更使用新处理目录。重跑先校验缓存哈希，复用有效产物；使用`--retry-failed`显式恢复失败件，模型调用上限绑定每件冻结批次的累计调用数，不代表整个全国任务的费用估算。每件默认最多执行3次（`--max-job-attempts`），失败只在显式`--retry-failed`时重试。冻结清单后新增文件须建立新的处理输出目录；原件必须位于该国家的`pipeline/raw/`。

将`processing/review-queue.json`交给独立审核者，逐件核对原件全部页、原文、中英文全文、日期、条款、数值和图表关系。使用[三阶段处理](staged-pipeline.md)的`review-import`及`repair-import`闭环问题，不由初译模型自审。当前CLI不自动调用云端强模型；独立记录尚未导入时保留待复核，不能生成通过结论。对未完成件继续保留队列与原因。

复用OCR、表格等派生缓存前校验输入、实现及依赖配置和全部产物哈希。将失败或不兼容目录保留为历史证据，选择新的有界attempt目录；不要因收据写着completed就直接复用。已有三阶段冻结准备输入时，核对原件、prepared和阶段计划绑定后沿用，保护已完成模型片段，不能把新sidecar覆盖旧计划。分别记录模型请求超时、传输和JSON错误；历史通用错误缺少底层证据时保留原因未知，不倒推确诊。

按国家串行进入实际模型处理。新批量计划默认有界等待国家处理锁1800秒，使用`--processing-lock-wait-seconds`显式调整并冻结；普通staged默认0秒保持既有行为。记录等待时间，独立于模型推理时间。达到等待上限时将任务记为`deferred`并停止本轮后续调度，重跑恢复，不把排队计为处理失败次数。已有批量计划缺少等待字段时沿用0秒；改策略使用新输出目录，共享原件和模型内容缓存，不覆盖旧计划。

遇到组织图或不可安全区分的重叠框线，保留该页原OCR并在sidecar的`visual_structure_issues`记录页码、原因和原图/OCR路径；继续处理其余页面。将每项问题冻结为独立复核的强制质量标记，缺少具体关系恢复和原图核验证据时不能通过。隔离页没有变成表格，并不代表组织关系已恢复；不得根据低成本模型平铺的标签推断父子关系。

## 计量与交付

报告目录访问、原件归档、OCR、表格重建、模型推理、修订和独立复核的实际耗时、调用与token。重跑复用不重复累计历史OCR/模型时间。将本地模型API费记0、订阅归属与硬件电力和总费用未知记null。保留初次失败和后续修订记录，交付覆盖缺口、各状态数量、批次ID、实际国家目录及两种可读报告。

使用`bulk_report.py`汇总多个来源批次和处理/复核批次，不修改运行中的队列。该入口从工程目录外同样可运行：

```text
python "SKILL_DIR/scripts/bulk_report.py" --root "WORK_ROOT" --jurisdiction Indonesia --archive-batch ARCHIVE_BATCH --process-output "PROCESSING_DIRECTORY" --review-batch INITIAL_BATCH --review-batch REPAIRED_BATCH --output "REPORT_DIRECTORY"
```

重复相应参数汇总多个批次。将源状态和模型事件的当前字节保存为哈希寻址证据快照，避免后台任务更新文件后报告哈希失配。重新核验原件与审核产物哈希、全部质量标记和修订问题闭环；并列保留初稿失败与修订通过。生成`execution-report.json/md/html`，注明静态快照时间、仍需核实的全量覆盖、正在处理或待复核状态。汇总记录不自动把整个法域置为完成；缺失终审或未知总量须继续保留缺口。

纯下载入口在`fast-download/status.json`原子保存累计详情数、按SHA去重的成功原件数、失败文件引用和分类原因、执行并发及数据时间，供外部看板读取；仅根据已提交下载收据统计，不在刷新时重新哈希所有原件。将Web的页面刷新时间与下载数据时间分开，将配置并发与本轮并发分开。`finished`且存在失败时表示队列结束但有缺口，不表示全国法规收齐；结合受信服务状态区分运行、暂停和结束。

运维摘要将`operations`（详情任务互斥分区）、`identity_counts`（五字段元数据法律身份归并）、`file_counts`（SHA去重及角色）和`timing`分开。只将完整收据且全部文件成功的详情任务计已下载；单列失败/不完整，不用已尝试数替代完成数。用执行器实际活跃任务和未投递队列记录下载中/待下载；停止后不把上轮活跃任务显示为仍在下载。缺少身份、文种、用途或版本证据时标待核验；同身份跨来源、跨版本不增加法规数，不以公布日、文件格式或字节变化推断版本。计时显示批次创建至快照/结束历时（含等待和暂停），缺精确活跃时段时不估算实际下载耗时。

修复超限等可恢复失败后，仅在线上目标机器执行验证和重试（当用户指定线上验证时，不在本机跑采集/测试）。用`bulk_download_fast.py ... --workers 5 --retry-failed --max-file-mib 512 --refresh-failed-details`记录本轮上限覆盖及源码哈希，不改原冻结计划。流式64KiB写盘和分块SHA避免5路大文件占满内存；超限截断原件保持失败，提高上限后重新获取完整原件，不冒充断点续传。刷新失败详情时优先复用既有成功收据，即使URL索引缺失也不重下已验证成功文件。DPR纯时间缓存参数变更的旧失败引用保留历史，当前集合不重复累计；不移除签名或未知查询参数。

将官网明确未提供原件、返回Access Denied及浏览器工具不可用分开记录。403拒绝页不是PDF；正常官方备用入口或浏览器未拿到完整字节时保持失败，不使用搜索工具可读内容、翻译件、同名其他语言文件代替原件。纯下载阶段不启动OCR、翻译或模型复核。

## 冻结目录直接归档到OSS

当用户明确要求按既有目录总数下载并统一存储OSS时，使用 `python -m law_crawler.census_to_oss`。按[显式运行配置](runtime-configuration.md)提供 `--jurisdiction`、`--census-root`、新 `--output`、`--bucket`、`--endpoint`、`--region`、`--prefix` 和 `--workers 5`。来源从顶层冻结目录计划读取，或用重复的 `--source` 指定子集；总量按实际记录计算，`--expected` 仅作为可选断言，`--old-metadata` 仅在复用旧缓存时提供。实际执行另传工程外600权限的 `--credentials`，仅冻结时无需凭据。先用 `--freeze-only` 核对数量、生成不可变队列哈希和计划，再用 `--limit 14` 验证跨平台原件、OSS、复用及清理，最后去掉limit从同一SQLite队列续跑。通过 `--platform` 限定验收来源，不改变总队列；已尝试失败项只在显式 `--retry-failed` 时重新入队。

此模式按用户认可的原始目录条目口径执行，不擅自删除日期未知、截止日后或待分类材料；将这些范围标记原样写入元数据。开发环境材料不混入生产队列，无官方详情URL的行另存证据。总任务数不是法规身份数，原件数另按SHA统计。

按来源轮转调度，避免一个受阻平台阻塞其他来源。每条详情保存独立结果；共享URL缓存和DPR已验证缓存参数归一化，优先复用旧成功原件。只归档明确官方原文链接；返回错误页或PDF链接格式不符时记录失败/待核验，不把HTTP200自动计作下载成功。官方multipart包保留原字节并标记封装PDF待核验，不自行解包替代原件。

将新文件临时缓冲到本批 `staging/`。原件和该详情元数据均完成OSS回读SHA核验后，仅清理本批临时文件；旧 `pipeline/raw` 不动。可用空间低于运行保留阈值（当前5GiB）或OSS401/403时停止领取新任务，保存暂停原因；不要无限重复失败或继续写满磁盘。不得把上传失败的原件删掉。缓存仅为加速提示，缺失缓存仍需查询OSS并校验对象，不能靠缓存记录证明上传成功。

用 `status.json`、`report.md`、`report.html` 查看总量、待下载、下载中、已完成、无原件、失败、不完整、OSS唯一文件数及字节数。只有下载和OSS元数据都成功的详情计入completed。将服务是否运行、执行耗时和目录/历史版本完整性分开；纯归档阶段禁止自动接入OCR或翻译。

### 修复“未发现原件”

先冻结该状态的目标ID清单、原始队列备份和状态快照，再按平台检查官方API文件字段、已归档详情及当前官方入口。区分解析遗漏、空文件名/占位链接、书目只有封面、官方明确暂无文件、HTTP200访问拦截及真实正文。保留全部授权目录条目；识别出非法规书目也不能擅自删除目标或把封面作为正文。

使用 `census_to_oss --retry-status no_original --retry-run-id UNIQUE_ID` 仅重新排队该分区；可加 `--platform` 限定平台。重跑计划和旧outcomes写入 `retries/UNIQUE_ID/`，同一run-id重启不再次排队已尝试任务。不要用 `--retry-failed` 混入用户未要求重跑的其他失败分区。

将跨官方来源补收与原站下载分开记录。全国性法规须同时核对文种、编号、年份及完整事项标题；只剥离开头明确的文种编号年份前缀，不能遇到任意“tentang”就截断修订事项，也不能用模糊标题或推测年份合并。部门规范另核对机关。严格匹配只解决法规身份，不能证明全部历史版本或附件齐全。

对自动严格匹配未通过的候选，允许独立审核者依据原件逐项裁定纯拼写、介词、历史正字法或明确简称差异；核对正式身份及正文中完整的主体、行为、对象和范围，记录双方原值、正文位置、证据SHA与差异不改变事项的具体理由。短标题省略的事项须由操作性条款明确佐证，不能凭目录或常识补全。保留旧待核结论并另建审核记录，不将个案裁定变成全局模糊匹配或自动删词规则。涉及机构主体、人员名单、数量、编号年份、版本、国家限定或事项范围的实质差异，缺少排除错件的证据时继续待核。

保留编号后缀：例如`68/M`不能按结构化目录中截短的`68`与另一法规匹配。标题或原件出现后缀而字段缺失时，退出纯数字身份自动匹配，保留待核；不要因此全局否定一份本身正确、只是与当前目标不同的原件。

使用文字层或HTML正文取证时，保存完整的受限提取文本，使`page_texts`及`first_page_text`与对应SHA逐字节一致；展示截断不得修改证据正文。`dpr_body_evidence`仍限制原件大小、HTML 2MiB及PDF前两页，不把前两页核验解释为全文或附件完整性验收。发现历史文本被截断但SHA来自全文时，保留旧证据并标记完整性失败；从已核验原件重新提取到新的输出文件，绑定新旧证据，不修改旧SHA来制造一致。

区分“附件是否齐全尚未核验”与“官方刊本明确缺附件”。后者在冻结修复项的`evidence`中记录`primary_text_identity_verified: true`和非空字符串列表`known_missing_attachments`，逐项说明缺少的附件；同时保留刊本声明的原文、页码、页图及原件SHA。主体身份通过独立复核后归档已有正文，执行器将任务记为`incomplete`，将缺件说明写入OSS元数据、原因和队列，不计入`completed`。元数据上传失败仍保持原队列状态；同一计划重跑跳过已转为不完整的任务，补齐附件须另建有证据的新修复流程。不要把全部附件未经核验这一常规未知状态虚构为已确认缺失。

遇到HTML末尾的`Lampiran`或`Penjelasan`占位时，检查原始HTML的链接及相对地址，不凭提取文本缺少附件便断言官网未提供。旧链接404时保留响应证据；仅把实际取得、核对正式身份及内容的官方替代文件作为补收结果，不把推测文件名作为成功证据。分别保存主体和附件的原字节SHA、OSS回读收据及角色，并通过冻结计划一起关联目标元数据。附件独立上传成功但尚未关联目标任务时，不增加任务完成数；不要修改已完成来源的旧outcome来夹带新附件。

为仍处于`no_original`的目标复用已核验正文并补入另行归档的附件时，在跨来源修复项显式添加`additional_verified_attachments`。每项固定`role: attachment`、`attachment_kind: annex`或`official_explanation`、已批准正文的`parent_primary_sha256`、原始`receipt`、`evidence_report_path`及其SHA、`full_text_sha256`和归档信封`metadata_sha256`。将证据报告绑定目标ID、来源ID、正文SHA、附件SHA及身份审核结论；不得仅提供一个OSS地址。执行器按来源平台核验官方主机，并回读信封与原件，全部成功后合并目标文件角色及元数据；失败保持目标状态，重跑跳过已完成项。该入口不重下已验证文件、不改旧来源结果，也不解除先前确认的缺件标记。

核对候选原件首页的正式编号、年份及完整事项，不以两站目录一致代替正文证据：官网也可能挂错附件。扫描件只为身份核验执行有界首页OCR，保留原件SHA、页码、页图SHA和识别文本；对识别冲突逐图复核，不将OCR置信度作为批准条件。通过`approved_primary_sha256s`限定批准复用的原件，不顺带导入同来源未核验的文件。发现真实错件时保留旧结果与拒绝文件证据，先保存并验证新的OSS元数据，再撤回完成状态；将来源ID和原件SHA记入批次`recovery/invalid-source-files.json`，阻止后续计划再次复用。区分文本层误识别与真实正文冲突，不能仅因OCR数字错误撤回正确文件。

区分原件身份与原文内部准确性。页图正式文种、编号、年份及完整事项均与目标一致，而正文引用或叙述另有数字冲突时，先独立判断冲突是否影响身份；不得自动修正原文，也不得仅因内部瑕疵就认定没有原件。确认身份后可按原字节归档，在修复证据`source_text_anomalies`中逐项保存位置、原值、页图SHA及判断依据，并标注`legal_content_accuracy: not_verified`。保留此前待核记录，新建审核结论及计划；冲突涉及正式身份、版本或完整事项且尚不能排除错件时，继续待核。

使用 `dpr_recovery_plan` 生成候选，再冻结带目标清单SHA、批次ID、目标与来源记录及outcome SHA的修复计划。通过 `recover_missing_original --batch BATCH_DIR --repair-plan PLAN_JSON --target-manifest TARGET_JSON --credentials CREDENTIALS --workers 5` 执行；先限量核验，确认后沿同一计划继续。计划旁保存同名 `.sha256` 文件，禁止重复目标。执行器复核来源正文角色、OSS原件字节和元数据归档，成功后才更新队列；保留原平台缺件事实及替代来源证据，不重复下载已验证原件。

连续执行短修复批次时，区分服务启动限流与下载失败。遇到 systemd `start-limit-hit`，先保存日志并核对 `MainPID`、实际进程、批次锁、当前单元绑定的计划及上一批结果；确认没有运行中的执行器且只是启动频次超限后，才对该单元执行 `reset-failed`，沿同一冻结计划重新启动。保留原有重启上限，不禁用限流，不重置已完成任务，也不因观察超时重启服务。

保留官网文件名的Unicode字符，不擅自删除零宽字符后推断地址。官方字段指定的第三方存储仅按已核实的精确主机和路径规则放行；不要扩大到任意外链。仅取得官方译文时归档文件并标记原文缺失，保持不完整；授权目录本身为FAQ或研究文章时可归档该材料，明确非正式法规，不能被全局摘要过滤误排除。
