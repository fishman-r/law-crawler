# 覆盖率能力矩阵

在用户询问“哪些平台已适配”“覆盖是否完整”“还缺哪些能力”时生成矩阵。分别呈现源码能力、已有运行证据和可计算的覆盖指标，不以下载完成率替代法规覆盖率。

## 准备范围

显式提供已登记的法域。可选传入目录普查批次和下载批次；不传时只评估代码能力，不联网猜测平台可达性。使用独立新输出目录，保留历次矩阵，避免覆盖旧报告。

```text
PYTHON SKILL_DIR/scripts/coverage_matrix.py --jurisdiction JURISDICTION --census-root CENSUS_ROOT --batch DOWNLOAD_BATCH --output NEW_REPORT_DIR
```

使用工作区自有索引时提供 `--registry-root WORK_ROOT`；默认读取完整 skill 内索引。通过 `python -m law_crawler coverage-matrix` 调用同一实现。命令只读现有状态与 SQLite 快照，不下载原件、不写 OSS、不调整生产队列。

## 区分三类信息

1. **静态能力**：目录发现、分页、原文候选、附件、版本、截止日。绑定当前实现文件的相对路径、符号与 SHA，区分已实现、部分支持、未知和未支持。存在分页方法不证明网站目录可穷尽；附件链接提取不证明附件齐全。
2. **运行证据**：目录已保存条数、分页状态、访问受阻原因、证据更新时间和冻结范围。报告生成时间不是网站刚访问的时间。平台别名及唯一匹配的官方子域归入同一平台，独立补充入口仍单列证据，不简单增加“平台总量”。
3. **覆盖指标**：仅用同一范围、同一单位且有证据支持的分子分母计算比例。队列完成条数除以冻结队列总量只能称“队列完成率”；OSS 对象数、法规数、目录项数、附件数和版本数分别报告。

目录 `observed_total` 可能来自已抓取条数或部分分组，不自动视为官方全集分母。零分母、范围不一致、未核验分母和数据矛盾保留 `null` 与原因，不能补为0%、截断为100%或反推全国总数。原文身份、附件全集和全部历史版本没有充分证据时保持未知。

需要提供可计算的目录覆盖率时，在来源状态的 `coverage_evidence.catalogue` 中保存独立审核声明：`review_status: independently_verified`、`reviewer`、`review_note`，以及 `numerator`、`denominator` 和 `evidence`。分子分母都须给出整数 `value`、`unit: distinct_detail_urls` 和相同 `scope: {platform, cutoff, versions}`；`platform` 对应该来源目录名，`versions` 对应明确冻结的版本范围。分母另给 `basis: official_explicit_total`；证据逐项绑定来源目录内的文件 `path`、`sha256` 和官方 `source_url`。实际分子必须与当前目录数据库一致。保留原状态和原证据，使用新审核批次产出此声明；不能为显示百分比而补造审核者或分母。

## 处理缺口

判定平台归属时使用已登记平台、显式别名或唯一目录入口主机。不要仅凭 `allowed_hosts` 认定存在目录适配器：聚合器可能只允许下载成员站点的原件。修改域名映射后定向运行 `test_capability_registry.py` 和 `test_coverage_matrix.py`，覆盖单聚合器成员域名、多个入口歧义及合法备用域名。

按矩阵中每个平台的缺口安排下一步：未适配来源补适配；分页不完整补分支与重复页核验；来源受阻查官方入口；分母未知收集官方目录范围证据；附件缺失走附件续收；历史版本未知先取得版本清单。不要因队列已结束而删除缺口。

对比新旧矩阵时核对索引、源码和计划 SHA、截点及版本范围。索引发生变化只能说明当前声明范围与旧批次可能不同，不能把旧批次成功比例直接用于新范围。交付 JSON、Markdown、HTML，并在报告首屏说明能够证明什么、仍不能证明什么。
