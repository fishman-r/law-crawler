# 原始归档、低成本处理与独立复核

## 选择范围

在用户明确国家/法域且已登记索引、明确要求原文处理后使用此流程。沿用当前任务已确认的输入，不再次询问元数据模式。将已确定的官方正文、详情和附件 URL 放入有限清单；不因格式、发布日期、正文身份判断提前丢弃已列出的响应。把“所有清单条目均尝试归档”和“整个网站全部采集”区分开。

执行程序去重、可追溯文本提取和格式化，再使用低成本模型翻译。保留原始字节，不用模型改写原文。把语义相似、跨版本、跨来源的法规身份关系保留为待确认；不要因模型判断相似而删除历史原件。沿用既有采集命令做目录发现和有证据的最新版本选择，新流程只处理给定清单，不能证明全站最新。

## 准备运行环境

使用完整 Python 3.10+。在本地准备可访问的 Ollama 服务及已安装模型，检查实际内存和小样本质量后选模型，不假定任何模型永远性价比最高。处理PDF时使用已安装的 `pypdf` 或 `pdftotext`；缺依赖时保留原件并报告失败，不自动下载模型或安装软件。对没有文本且未提供完整逐页转录的PDF返回待OCR，不将部分页面当作完整正文。对有文本的PDF仍要求视觉复核图表、签署页和字符映射。

先按[工作区准备](workspace.md)初始化独立工作区。把 `SKILL_DIR`、`WORK_ROOT`、输入路径替换成真实路径；无需工程根目录或专用agent接口。

清单示例：

```json
{
  "documents": [
    {
      "id": "sample-regulation",
      "url": "https://OFFICIAL_HOST/path/document.pdf",
      "title": "官方文件标题",
      "source_language": "id"
    }
  ]
}
```

将 `OFFICIAL_HOST` 替换为索引内来源或已经核对的官方附件入口。用可选 `document` 对象携带既有元数据schema，原样保存公布日期、法域和证据；不让模型猜补未知日期。另可用 `path` 替换 `url` 导入本地原件；程序冻结本地输入哈希，重跑时拒绝已变更输入。不要将登录页或错误响应误称为法规正文。

执行翻译前按[法律翻译文体](legal-translation.md)在manifest顶层指定`translation_style_path`。保留完整文体配置及来源，使用其冻结内容进行初译、回退及独立复核；不要把文体选择放入模型连接配置。

模型配置示例（模型必须实际存在）：

```json
{
  "provider": "ollama",
  "base_url": "http://127.0.0.1:11434",
  "model": "qwen3:8b",
  "timeout": 180,
  "num_ctx": 8192,
  "max_output_tokens": 2600,
  "temperature": 0
}
```

将 `timeout` 视为网络操作超时，不宣称是包含DNS、排队等操作的硬性总时限。按硬件调整上下文和输出上限；截断响应会失败，不能提交残缺JSON。当前流水线只开放本地Ollama；通用客户端的OpenAI-compatible支持不等于已启用付费批处理。不要在配置、收据或报告中保存密钥。

## 扫描件、混合PDF与复杂图表的逐页转录

先保存官方原始PDF。需要自动识别时使用[本地OCR入口](local-ocr.md)，成功后将sidecar交给本流程。原文字层为空、乱码或丢失图表关系时，渲染全部页面，使用可用OCR或人工视觉转录生成独立JSON；不要覆盖PDF，不把人工转录称作自动OCR。为每页记录实际方法、工具/编辑者、证据及完整文本。保留日期、条款、表格列名/单元格对应、合并单元格含义、脚注和图表连线；组织图可用缩进树。不能识别时明确标注未知并要求修订，不能猜补。

遇到日期、印章或公报号变成异常字形时，先用另一可用PDF渲染器交叉检查，并记录引擎/版本与页图路径。文字提取器、图像渲染器都可能丢失嵌入字体；单个渲染结果不能证明原件缺字。仅在实际可读页图支持时恢复数值，无法确认时保持未知。区分原生文字PDF、扫描底图带OCR层和无文字层扫描件，不只用非零字符数判断来源类型。

在manifest文档条目添加 `"transcription_path": "TRANSCRIPTION.json"`，相对路径按WORK_ROOT解析。结构如下：

```json
{
  "version": 1,
  "pdf_sha256": "原始PDF的64位小写SHA256",
  "page_count": 2,
  "pages": [
    {"page": 1, "text": "第1页完整转录", "method": "ocr", "producer": "实际OCR工具及版本", "evidence": "第1页图路径及核对说明"},
    {"page": 2, "text": "第2页完整文字层", "method": "text_layer", "producer": "实际提取器及版本", "evidence": "第2页图路径及核对说明"}
  ]
}
```

将需要出现在派生全文中的签名、图章、图表和页脚视觉说明直接写入对应 `pages[].text`，使用明确的非正文标记。不要只放在自定义 `non_text_notes` 等字段中：此入口只将 `pages[].text` 拼接为翻译源文，自定义字段仅随sidecar归档。复核时同时检查sidecar完整记录与三语稿。

将 `method` 设为 `manual`、`ocr` 或 `text_layer`。按连续页码覆盖全部实际PDF页；真正空白页使用 `text: "", blank: true` 并解释页证据。混合PDF同样声明全部页。脚本冻结sidecar哈希，先归档原PDF，再归档sidecar，处理前核对PDF哈希、真实页数和转录哈希。修改输入后建立新批次，不篡改旧计划。转录字数覆盖不是原件完整性的证明，复核者须逐页检查；所有转录均增加强制质量标记并绑定审核产物。

将转录准备耗时与低成本翻译、强模型修订、独立复核分开记录，不能把提前的人工工作排除后宣称全自动低成本通过。未配置可用OCR时可用明确记录的人工视觉转录；没有完整转录时保留needs_OCR失败，不仅翻译有文字的页面。无需依赖特定agent或操作系统的OCR工具。

## 冻结计划并运行

```text
python -X utf8 "SKILL_DIR/scripts/staged_pipeline.py" --root "WORK_ROOT" --jurisdiction Indonesia --manifest "MANIFEST.json" --model-config "MODEL.json" --batch-id id-sample-001 --stage run --chunk-chars 1500 --max-calls 30
python -X utf8 "SKILL_DIR/scripts/staged_pipeline.py" --root "WORK_ROOT" --jurisdiction Indonesia --rerun-batch id-sample-001 --stage run
```

使用 `--stage capture` 先只归档；使用 `--stage process --rerun-batch BATCH_ID` 仅读取该批次已归档内容，不发起下载。`run`先完成清单全部归档再处理。使用 `--config PROPERTIES` 指定下载配置。将默认最多3次下载总尝试与模型调用上限分别记录；模型输出截断时仅允许一次回退，仍计入该批次总调用上限；其他模型失败不自动重试。回退先清理模型输入中的空行，对明确印尼语输入中的疑似字体乱码保留Unicode码点标记，不猜补内容，记录清洗映射并要求复核。原始文件和提取原文保持不变。已消耗或可能消耗的调用仍占用预算。修改模型、来源或分块策略时新建批次，保留旧计划与报告。

按 `downdloadDir` 的国家子目录保存 `pipeline/`。在原件层按SHA复用相同字节，为不同来源保留收据；校验缓存哈希后才能复用处理结果。保留每轮状态和原因，区分原始归档成功、文本提取成功、模型处理成功和独立复核通过。

将无损清洗限定于可解释的编码、换行和结构处理。保留字段名、条款编号与附件边界；不要摊平成无名数字，也不要向可读Markdown添加XML字段路径括号。检测数字遗漏、异常短译文、中文汉字比例不足及直接复制源文；把这些检查作为风险提示，不当作语义正确的证明。

## 按复核问题修订并重验

将每项复核问题保留为稳定的 `issue_id`。先尝试对完整条款定向重译，不再把短字符块直接视为独立法律句子。保持带字母条号（如16A、16B）、斜杠法规编号及机构实体；检查“已变成中文”之外的语义和引证。定向重译仍有错漏时升级给修订者，记录其模型、耗时与未知费用，不无限重试低成本模型。

让修订者对照原始页图完成派生原文与中英文稿。恢复文字层未提取的日期时附原件页证据；将组织图每条连线转成明确的父子关系，保留同级节点、原标签和子单位。把页内图像转录说明与法规正文明确区分，不从电子签名图形推断签名有效性。生成Markdown时保留树的空格和换行。保留全部旧产物，不直接改旧译稿文件。

准备修订清单（完整字段均需提供）：

```json
{
  "parent_batch": "OLD_BATCH_ID",
  "reviewer_or_editor": "editor-identifier",
  "model": "实际编辑模型；不可确认精确版本时明确说明",
  "duration_seconds": 120,
  "cost_usd": null,
  "files": [{
    "id": "与父批次一致的文件id",
    "base_artifacts": [],
    "source": {"path": "ABSOLUTE_SOURCE_PATH", "sha256": "SHA256"},
    "zh": {"path": "ABSOLUTE_ZH_PATH", "sha256": "SHA256"},
    "en": {"path": "ABSOLUTE_EN_PATH", "sha256": "SHA256"},
    "changes": [{
      "issue_id": "R01",
      "description": "具体修改及理由",
      "evidence": [{"page": 2, "detail": "原件页内容与修订对应关系"}]
    }]
  }]
}
```

将 `base_artifacts` 替换为父批次 `review-request.json` 的完整清单，不保留示例空数组。为每个旧问题提供且仅提供一项change；使用实际文件哈希与实际编辑耗时，不能获得的费用或耗时记null。原文改动必须有页证据。当前接口要求父批次所有文件已完成处理且均有待修订问题；若有未处理失败文件，先解决失败，不通过修订导入遗漏它们。

```text
python -X utf8 "SKILL_DIR/scripts/staged_pipeline.py" --root "WORK_ROOT" --jurisdiction Indonesia --stage repair-import --parent-batch OLD_BATCH_ID --repair "REPAIR.json" --batch-id NEW_BATCH_ID
python -X utf8 "SKILL_DIR/scripts/staged_pipeline.py" --root "WORK_ROOT" --jurisdiction Indonesia --stage repair-import --rerun-batch NEW_BATCH_ID
```

让脚本冻结父计划、父复核、旧产物和新输入哈希，再保存到国家目录 `pipeline/revisions/NEW_BATCH_ID/`。重跑复用冻结输入，不下载、不调用模型、不覆盖不同字节的修订产物。禁止对修订批次运行旧process流程。修改修订输入时新建下一批次，不覆盖已冻结文件。

保持已审核产物与复核请求不可变。渲染格式、提示语或派生结构发生变化时，使用新的内容寻址产物和新批次；不得在原路径覆盖旧字节，也不得让重跑悄悄替换已被审核引用的请求。相同输入和渲染结果可复用；缓存复用仍须验证产物与复核哈希。

把新 `review-request.json` 交给另一位独立复核者，逐项核对旧问题及全稿，禁止修订者自审。仅在无未解决问题、全部质量标记有核验证据时导入pass；否则按新issues继续建立修订批次。保持通过结论与具体哈希绑定；产物上的“待复核”生成时说明不随审批覆盖，最终状态读取同批 `review.json`。

## 独立复核

读取批次生成的 `review-request.json`，安排不同于低成本处理模型的独立复核者。将原件和全部派生产物交给复核者，逐段比对原文、中文与英文；对PDF查看完整页图，检查日期、义务/例外、数值、引证、图表、遗漏与重复。不把处理模型的自评当独立复核，不只审查摘要。

在请求记录基础上保留每个文件的完整 `artifacts` 哈希绑定，填写实际 `reviewer`、`model`、`cost_usd`、复核耗时及每文件 `verdict`（`pass`或`needs_revision`）、`issues`。将实际复核耗时写入 `duration_seconds`（秒）。通过时对每个质量标记填写 `resolved_quality_flags: [{"flag": 原始标记对象, "evidence": "具体核验记录"}]`；缺乏证据时保持待修订。保存复核记录后导入：

```text
python -X utf8 "SKILL_DIR/scripts/staged_pipeline.py" --root "WORK_ROOT" --jurisdiction Indonesia --rerun-batch id-sample-001 --stage review-import --review "REVIEW.json"
```

将该导入视为外部模型审核记录的验证，不视为CLI自行调用了高质量模型。拒绝空审核、漏项、已变化产物和无解释的质量风险。译文需修订时保留失败报告及证据，创建可追溯新产物后重新审核；不得手动把失败状态改成通过。复核通过只针对绑定的产物内容，不代表法规现行效力或唯一最新版本。

## 交付结果

交付原始文件、原文/中文/英文派生稿及元数据、批次ID、每阶段JSON/Markdown/HTML报告。报告实际处理范围、质量问题、复核结论、各阶段耗时、模型调用与token，以及重跑复用情况。

将本地模型API账单记为0；将未测量的电费、硬件折旧和无法取得的高质量订阅模型费用记为 `null`。不要用0代替未知总成本。记录失败调用可能产生的未知token/费用。将原始传输完整率、文本分块覆盖、翻译质量和复核通过率分开呈现。分开列出首审与终审问题数、视觉转录准备、低成本推理、强模型修订和独立复核耗时；人工估算单列为estimated字段，不并入实测总和。保留初稿失败及修订链，不以终审通过改写历史首审结论。

当前边界：通过[本地OCR适配](local-ocr.md)调用已安装引擎，也可导入经溯源的外部OCR/人工逐页转录；语义去重不自动合并记录；PDF复杂版式需要视觉复核；新流程不自动发布到旧的正式法规目录。收据保存每次请求的最终响应，中间3xx跳转响应不单独归档。HTML/XML/JSON转换保留可检查的结构，但仍需复核者确认法律正文身份与完整性。

## 2026-10-21印尼样本反馈

将“机器处理成功”与“复核通过”分开验收。首轮完整5页修正规章实跑中，本地模型出现部分中文稿未翻译、签署页乱码和组织图关系损失；独立复核要求修订。用这一结果验证拦截机制，不把该模型已能稳定完成法规翻译作为结论。对于同类签章页和图表，保留原件并补足可靠提取或视觉重建后再翻译和复核。

### 已验证的修订样本（2026-10-21）

参考印尼贸易部长2026年第24号规章的5页样本：定向低成本重译仍出现16A→16，经独立编辑整稿修订后，另一复核者逐页检查并关闭10项问题。保留原PDF和旧稿；补齐日期/公报号时提供第4页视觉依据，恢复组织树时逐条核对第5页12条边。将此结果视为人工参与的单样本验证，不将其解释为自动OCR、自动图关系恢复或本地模型质量保证。分别记录定向推理、历史编辑、当前导入与独立复核耗时；重跑导入不得重复计入编辑耗时或费用。

### 扩样验证（2026-10-21）

验证3份完整法规共11页：原生文本PDF、真实无文字层扫描及组织图各1份。15次本地模型调用的首稿有20项问题；经编辑和另一agent逐页终审全部关闭。扫描使用人工转录，未验证自动OCR引擎；未覆盖表格样本。保留未能可靠辨认的非正文验证URL，不把质量通过扩张为逐字无损或法律效力判断。将本轮渲染器差异、法规层级误译及重跑覆盖问题纳入前述门控；按内容寻址保存渲染产物，并在已审核请求变化时要求新批次。
