# 统一 HTTP 下载内核

维护下载入口时复用 `scripts/law_crawler/download_transport.py`，不要在适配器中另写响应读取和重试策略。内核只负责传输，不判断法规身份、法律效力或附件是否完整。

## 选择入口

- 使用 `raw_capture.capture` 归档原始响应、错误页和部分字节，沿用收据、内容哈希与缓存。全量下载及 OSS 下载通过此入口传输文件。
- 使用传统 `fetch` / `official_fetch` 返回有大小上限的字节与最终 URL，供目录解析和兼容状态库使用；单次调用只发起一次业务请求，由最外层 `retry_fetch` 控制重试。网络读取按块进行，但返回完整 `bytes` 的接口仍需容纳上限内的文件，不宣称恒定内存。
- 使用 `Census.fetch` 处理目录普查，保留 CookieJar、目录查询 POST、12 MiB 上限、成功缓存与逐次请求记录。不要将目录查询 POST 的重试用于有外部写入作用的接口。
- 保持模型 API、浏览器操作和 OSS SDK 在各自接口内；它们不是官方法规 HTTP 下载入口。

## 保持共同约束

按 64 KiB 分块读取响应并检查 `Content-Length`、空响应和大小上限。保存原始字节，不以服务端文件名代替实际格式与哈希。传输失败或超限的部分字节不能成为成功缓存。不要为统一内核取消官方来源白名单、TLS 证书校验、原归档的路径保护或已有证据链。

为一次业务请求保留唯一重试层，默认最多三次总尝试，包含首次。对 408、425、429、500、502、503、504 和暂时网络故障使用统一重试策略；403、404、证书验证失败和体积超限不自动重试。指数等待加入小幅随机抖动，指数部分上限 30 秒；遵守 `Retry-After` 的秒数或 HTTP 日期，不因没有停止事件而忽略它。

服务端要求超过 300 秒冷却时，记录延期原因和最早重试时间，本轮停止自动重试；不要截短冷却后提前请求。分段等待以便响应停止请求。重跑前读取尚未到期的服务端冷却，不把立即另开批次视为解除限制。

保持 HTTP 失败、传输不完整、文件格式异常和正文身份冲突各自的状态与原因。成功缓存复用不是新的网络尝试。复核批次报告、下载收据和普查逐次记录中的尝试数，防止外层三次重试叠加内层三次而变成九次请求。

## 验证变更

在用户指定执行环境验证真实 HTTP 响应：短暂故障后成功、429 冷却、403 单次失败、截断响应、超限、停止、成功缓存零重复请求，以及不同入口获取相同字节的 SHA 一致性。另用有界官方样本验证连通和原件哈希；将夹具测试、官方样本与生产全量状态分开报告。

保留任务级续跑。本内核不声明支持 HTTP Range 字节断点续传；中断文件仍按现有策略重新获取。
